# Hermit PEBS 实测评估

> 汇总 2026-10-06 至 2026-10-12 的 Memcached、数组、Redis、YCSB、XGBoost 实验。
> 详细原始报告在 [PEBS 历史报告](../archive/pebs/)，原始数据在
> [PEBS 原始数据](../../tools/rdma/results/pebs/)。

## 1. 结论摘要

1. **采样开销低**：无换页时 CPU/请求约 +0.5%–1.2%；换页压力下纯采样通常为 0–6%；
   Redis 约 1.8%–2.6%，XGBoost 高频约 1.6%。
2. **Memcached 上策略收益显著，但强烈依赖对照口径**：相对“大 folio + 4 KiB WR”
   基线可高数倍；相对纯 4 KiB 基线则可能略慢。报告中的大百分比不能脱离基线解读。
3. **多负载矩阵没有一致收益**：1323 个样本中数组、Redis、YCSB、XGBoost 的
   policy 净变化中位数在 −0.10% 到 +0.35% 之间，读流量也基本不变。
4. **根因是时间局部性**：策略依赖同一 region 的历史样本；一次性/流式访问在
   swap-in 决策时没有可用历史，退回静态页档。
5. **策略仍在早期**：它主要避免“大 folio 过度读回”，还不是通用的页面选择或
   前瞻式预取策略。

## 2. 对照口径

同一组数字在不同基线下含义不同，阅读时必须先确认：

| 配置 | 采样 | 决策 | 作用 |
|---|---|---|---|
| `off-original-mask` | 关 | 只允许 4 KiB（mask `0x1`） | 最早的 4 KiB WR 基线 |
| `off` | 关 | 允许大 folio/全部页档 | 只放开分配、不采样的基线 |
| `off-same-pages` | 关 | 与 static/policy 相同的页分配和传输 mask | 采样开销的同页对照 |
| `static-*` | 开 | 静态页档 | 纯采样开销 |
| `policy-*` | 开 | PEBS 动态决策 | 采样 + 策略 |

另外，2026-10-11 与 2026-10-12 两轮 pressure 的 `off` 语义不同：

- 2026-10-11：`base-pages-4k-v2`，全部 THP/mTHP 关闭，纯 4 KiB。
- 2026-10-12：`natural-pages-v3`，保留系统 THP/mTHP；`off` 是“大 folio + 4 KiB WR”，
  不是纯 4 KiB。

因此两轮 `off` 的绝对 QPS 不能直接比较；跨轮只能比较同一轮内的相对关系。

## 3. 采样开销

### 3.1 Memcached

| 场景 | 结果 |
|---|---|
| 无换页 resident（2026-10-06，固定 30000 QPS） | CPU/请求 +0.52%–0.79%，read p99 绝对增量 1.3–1.6 µs |
| 无换页 resident（2026-10-12） | 各配置相对 off-same-pages 约 1% 以内 |
| 换页 saturation（2026-10-06） | static-medium 相对 off 吞吐 −6.2% |
| 换页 pressure（2026-10-12） | static-medium 与 off-same-pages 基本持平；配对中位数 4.6%，区间跨零 |

采样频率（load period 19997/1999/199）对无换页吞吐几乎没有影响；真正被影响的是
策略能拿到多少有效样本。覆盖足够后，继续提高采样率不会线性增加收益。

### 3.2 其他负载

| 负载 | 纯采样开销（static vs off） | 说明 |
|---|---:|---|
| anon-1t/8t，full 与 chunk64k | ≈0% | 扫描阶段变化很小 |
| Redis | +1.8%–2.6% | 各页档均显示正增量 |
| YCSB | ≈0% | 低频接近零，但逐页有约 −7%–+7% 波动 |
| XGBoost | ≤1.6% | 高频档增加较一致 |

这些数字是应用阶段耗时，不含填充和换出的全部成本，也不等于全系统 CPU 开销。

## 4. Memcached：收益与基线

### 4.1 2026-10-06（64 KiB THP，纯 4 KiB 基线可用）

| 配置 | QPS 中位数 | read p99 µs | CPU µs/请求 | RDMA read KiB/请求 |
|---|---:|---:|---:|---:|
| off-original-mask（仅 4 KiB） | 44,492 | 12,848 | 168.88 | 49.64 |
| off（大 folio，不采样） | 63,424 | 10,156 | 118.41 | 43.58 |
| static-medium（采样，静态） | 59,489 | 10,773 | 122.88 | 44.04 |
| policy-medium（采样 + 策略） | **145,338** | **5,444** | **48.90** | **3.59** |

报告中的配对中位数：policy 相对 off **+124%**、相对同频 static **+136%**、
相对仅 4 KiB 基线 **+223%**；RDMA 读流量降低约 86%–91%。

### 4.2 2026-10-12（自然页分配）

| 配置 | QPS 中位数 | read p99 µs |
|---|---:|---:|
| off（大 folio + 4 KiB WR） | 23,965 | 39,733 |
| off-same-pages | 23,835 | 36,868 |
| policy-medium | 152,357 | 8,395 |
| policy-high | 165,975 | 7,408 |

这一轮的 `off` 用大 folio 分配但只允许 4 KiB WR，单次 fault 可能产生大量 WR
和过度读回；策略把换入 folio 收紧后收益很大。它说明策略能修正“分配粒度与传输
粒度错配”，但不能说明策略优于纯 4 KiB。

### 4.3 2026-10-11（纯 4 KiB 基线）

| 配置 | QPS 中位数 |
|---|---:|
| off（纯 4 KiB） | 270,710 |
| off-same-pages（64 KiB 页） | 98,396 |
| policy-medium | 238,673 |
| policy-high | 210,925 |

在同一轮中，policy-medium 相对纯 4 KiB off 约 **−11.8%**。这是重要的反向证据：
**当纯 4 KiB 已经是最优选择时，策略的采样和决策开销是净成本**。因此 headline
百分比必须同时给出“vs 纯 4 KiB”和“vs 自然大 folio”两个口径。

## 5. 多负载矩阵（2026-10-07/08）

规模：1323 个样本 = 441 组 × 3 重复；9 个页档 × 7 种配置。所有样本通过基础验收，
恢复错误为 0。

|---|---:|---:|---:|
| anon-1t-full | −0.05% / +0.01% / +0.23% | +0.32% / +0.44% / +0.89% | ≈0% |
| anon-1t-chunk64k | +0.06% / +0.07% / +0.18% | +0.40% / +0.60% / +0.75% | ≈0% |
| anon-8t-full | −0.10% / +0.11% / −0.35% | +0.27% / +0.63% / +0.47% | ≈0% |
| anon-8t-chunk64k | −0.16% / −0.09% / −0.03% | +0.71% / +0.08% / +0.45% | ≈0% |
| Redis | +1.80% / +2.25% / +2.58% | +2.36% / +2.66% / +2.31% | +0.14% |
| YCSB | +0.03% / +0.28% / −0.73% | +0.60% / +0.00% / +1.14% | ≈0% |
| XGBoost | +0.05% / +0.27% / +1.57% | −0.08% / +0.28% / +1.45% | ≈0% |

中频 policy 相对同频 static 的跨页耗时变化中位数：单线程全扫描 +0.35%、
单线程 chunk64k +0.24%、8 线程全扫描 +0.16%、8 线程 chunk64k +0.32%、

Redis 79/81，四种数组配置仅 11–23/81。数组场景的样本覆盖不足以支撑有效决策。

## 6. 采样质量与有效性

- 2026-10-08 的 1323 个样本中，90 个出现 lost 增量，全部为 load period=199；
  单线程全扫描 static/policy 12/15、单线程 chunk64k 3/6、XGBoost 27/27。
- 当前 `lost` 同时记录 ring 处理异常和 `PERF_RECORD_LOST` 记录事件，不是逐条
  样本的精确丢失数，因此不能给出精确丢样率；只能确认高频档存在采样质量问题。
- Redis/YCSB 的 2048 KiB off 组大页读取占比为 0%，该配置应标记为“大页未生效”；
  其性能数字只代表实际发生的 4 KiB 路径，根因尚未定位。
- 全机 per-CPU 事件包含客户端等其他进程；区域跟踪只记录被启用的 mm，但采样
  开销和 `sampled` 计数仍是全机的，不能当作目标负载的独立采样率。

## 7. 适用边界

策略有效的前提是：**同一个 2 MiB region 在 swap-in 之前已经产生过足够的访问
样本，并且本次 fault 周围的访问密度可以被历史近似**。这适合热 key 反复访问、
局部 chunk 扫描等场景；不适合一次性顺序扫描、每个 region 只访问一次的负载。

因此当前结论应表述为：

> PEBS 页面策略可以在“大 folio 分配 + 稀疏访问”时显著减少过度读回，但在纯
> 4 KiB 已最优或一次性流式访问时没有稳定收益。下一步需要前瞻式预测、冷启动
> 策略，以及把原始 folio、换入 folio、RDMA WR 三个尺寸解耦。
