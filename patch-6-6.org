* 迁移 Hermit 到 Linux 6.6

当前新版目录为 =hermit-6.6=：

- 内核目录：=linux-stable=
- remoteswap 目录：=remoteswap=
- QEMU DRAM 验证目录：=tools/qemu-dram=

当前重点是 6.6 DRAM 模式和 5.14 profiling 点迁移。RDMA backend 还没有完整迁移。

主要缺口

vmscan 当前已经接上 profiling，但主要还是 native folio reclaim：hermit_try_to_free_mem_cgroup_pages() 仍包装 try_to_free_mem_cgroup_pages()，没有完全恢复 5.14 的 shrink_node_profiling/shrink_lruvec_profiling/shrink_page_list_profiling。

5.14 的 Hermit 定向 rmap 没有真正接入：rmap.c/pagewalk.c/vmscan.c 没有 hermit_try_to_unmap()、hermit_addr_vma_walk() 的完整实现接入。

batch swapout/TLB/batch account 的统计点已部分恢复到 6.6 folio reclaim 位置，但语义仍与 5.14 profiling 版本不完全一致。

frontswap/rswap 后端迁移状态：
- DRAM backend 已迁移到 hermit_backend_ops。
- swapout/store 已在 page_io.c 接入 hermit_backend_store()。
- swapin/load 已在 do_swap_page() direct path 和 swap_readpage() native path 接入 hermit_backend_load()。
- RDMA backend 仍未迁移，rswap_rdma_ops.c 中还保留旧 frontswap_ops 逻辑。

pref_request 相关接口在 hermit.h 里保留了声明，但缺少 5.14 那套结构定义和完整实现，属于残留骨架。

hermit_mem_cgroup_swapin_charge_page() 旧 page 接口不再作为主路径使用，6.6 当前主路径是 mem_cgroup_swapin_charge_folio()。
