#+title: Hermit 6.18

* 概览

本目录将 Hermit 迁移到 Linux =v6.18.38=。内核位于 =linux-stable=，当前
Hermit 分支为 =hermit-6.18=。

迁移后的数据路径不再依赖内核 frontswap：内核通过
=hermit_backend_ops= 调用 DRAM 或 RDMA backend。RDMA 客户端使用针对当前
内核构建的外部 Mellanox OFED 驱动、头文件和 =Module.symvers=；不要求构建
Linux 源码树内的 RDMA core。

当前实现包含：

- Linux 6.18 的 Hermit Kconfig、debugfs 控制面、统计系统调用和 profiling；
- remote-only swap slot 跟踪：远端 store 成功后跳过本地 swap BIO，失败时回落
  原生 swap；
- order 0–9 folio 的 DRAM/RDMA store、同步 load、direct async load 和 lazy poll；
- 大 folio 可用一个可变长 RDMA WR 传输，失败时自动改用多个 4 KiB WR；
- 远端 extent 在整个 folio 范围内事务化预留和提交，支持 partial invalidate；
- 运行时 order 位图和逐 order store/load/fallback/error 统计；
- memcg 接近 =memory.max= 时的定向异步回收；
- QEMU DRAM checksum、vmstat、backend 计数和本地 swap 写扇区验证。

详细迁移记录见 =docs/migration-6.18.md=。=docs/plan/= 下的 6.6 文档作为历史
记录保留。

* 构建内核

Hermit 的 6.18 Kconfig 直接要求 =X86_64=、=MEMCG=、=SWAP= 和 =DEBUG_FS=；
使用外部 rswap/DOCA OFED 模块还要求 =MODULES=。THP/mTHP 传输测试额外要求
=TRANSPARENT_HUGEPAGE=，并由 Hermit 选择的 =ARCH_WANTS_THP_SWAP= 自动得到
=THP_SWAP=：

#+begin_example
CONFIG_HERMIT=y
CONFIG_SWAP=y
CONFIG_CGROUPS=y
CONFIG_MEMCG=y
CONFIG_DEBUG_FS=y
CONFIG_TRANSPARENT_HUGEPAGE=y
CONFIG_THP_SWAP=y
CONFIG_MODULES=y
CONFIG_INFINIBAND=m
CONFIG_INFINIBAND_USER_ACCESS=m
CONFIG_INFINIBAND_USER_MAD=m
CONFIG_INFINIBAND_ADDR_TRANS=y
CONFIG_INFINIBAND_ADDR_TRANS_CONFIGFS=y
CONFIG_MLX5_CORE=m
CONFIG_MLX5_INFINIBAND=m
#+end_example

以下均是部署或实验策略，而非 Hermit 代码依赖：

#+begin_example
# 推荐为运行时 THP/mTHP 测试保留 madvise 默认策略
CONFIG_TRANSPARENT_HUGEPAGE_MADVISE=y
# CONFIG_TRANSPARENT_HUGEPAGE_ALWAYS is not set
# CONFIG_TRANSPARENT_HUGEPAGE_NEVER is not set
# 防止压缩内存路径截获远端 swap I/O
# CONFIG_ZSWAP is not set
# CONFIG_ZRAM is not set
# 若要与传统 LRU 基线对比才关闭；不是 Hermit 的 Kconfig 前提
# CONFIG_LRU_GEN is not set
# OFED DKMS 需要替换同名 RDMA/MLX5 模块，因此保持模块化
CONFIG_INFINIBAND=m
# 仅 tools/qemu-dram 回归需要
CONFIG_BLK_DEV_RAM=m
#+end_example

=CONFIG_THP_SWAP= 是 =CONFIG_HERMIT= 选择 =ARCH_WANTS_THP_SWAP= 后由 6.18
Kconfig 自动推导的；DOCA/OFED 的 provider 需要 =CONFIG_INFINIBAND=m=，从而
由 =updates/dkms= 下的 OFED 模块替换同名 in-tree 模块。THP/mTHP 的具体大小在运行时经 THP sysfs 和
=remote_order_mask= 选择；=BLK_DEV_RAM= 不是 dnet RDMA 测试要求。

构建：

#+begin_src sh
make -C linux-stable olddefconfig
make -C linux-stable -j"$(nproc)" bzImage modules
#+end_src

* QEMU DRAM 验证

本机没有 =/dev/kvm= 时使用 TCG：

#+begin_src sh
QEMU_ACCEL=tcg QEMU_CPU=max \
  ./tools/qemu-dram/validate-qemu-dram.sh
#+end_src

已构建内核和模块后可跳过构建：

#+begin_src sh
QEMU_ACCEL=tcg QEMU_CPU=max SKIP_BUILD=1 TIMEOUT_SEC=360 \
  GUEST_RAM_MB=2560 RSWAP_MEM_GB=1 SWAP_MB=1024 \
  MEMHOG_MB=1200 TMPFS_FILL_MB=400 \
  ./tools/qemu-dram/validate-qemu-dram.sh
#+end_src

验证脚本要求以下条件全部成立：backend store/load 均大于零、backend error
为零、=pswpout=/=pswpin= 增长、memhog checksum 一致，并且
=/sys/block/ram0/stat= 的写扇区数不变。最后一项直接验证 remote store 成功后
没有提交本地 swap BIO。

lazy-poll 回归：

#+begin_src sh
QEMU_ACCEL=tcg QEMU_CPU=max SKIP_BUILD=1 TIMEOUT_SEC=360 \
  GUEST_RAM_MB=2560 RSWAP_MEM_GB=1 SWAP_MB=1024 \
  MEMHOG_MB=1200 TMPFS_FILL_MB=400 LAZY_POLL=Y \
  ./tools/qemu-dram/validate-qemu-dram.sh
#+end_src

64 KiB mTHP 双向大 folio 回归：

#+begin_src sh
QEMU_ACCEL=tcg QEMU_CPU=max SKIP_BUILD=1 TIMEOUT_SEC=360 \
  GUEST_RAM_MB=2560 RSWAP_MEM_GB=1 SWAP_MB=1024 \
  MEMHOG_MB=1200 TMPFS_FILL_MB=400 BYPASS_SWAPCACHE=Y LAZY_POLL=Y \
  THP_SIZE_KB=64 REMOTE_ORDER_MASK=0x11 \
  ./tools/qemu-dram/validate-qemu-dram.sh
#+end_src

2 MiB THP swapout 回归把最后一行改为
=THP_SIZE_KB=2048 REMOTE_ORDER_MASK=0x201=。Linux 6.18 的 PTE swap fault
只聚合 order 2–8 的 mTHP，因此这个用例验证 order-9 大 WR 写入；64 KiB 用例
同时验证大粒度写入和回读。

串口日志位于 =tools/qemu-dram/_work/guest-serial.log=。

* RDMA 与外部 OFED

先为目标 =v6.18.38= Hermit 内核构建或安装 Mellanox OFED。=OFA_DIR= 必须
同时包含匹配该内核的 =include/= 和 =Module.symvers=。DOCA/OFED DKMS 的常见
目录是 =/usr/src/ofa_kernel-dkms/x86_64/$(uname -r)=；只有在
=/usr/src/ofa_kernel/default= 确实解析到当前内核目录时才能使用后者。

#+begin_src sh
make -C remoteswap/client \
  KDIR="$PWD/linux-stable" \
  BACKEND=RDMA \
  OFA_DIR="/usr/src/ofa_kernel-dkms/x86_64/$(make -sC linux-stable kernelrelease)"
#+end_src

若 OFED 安装在其他目录，覆盖 =OFA_DIR=。不要用另一内核或另一版 OFED 的
=Module.symvers= 消除 modpost 报错；symbol CRC 不一致的模块不能安全加载。

服务器和客户端启动参数见 =remoteswap/README.md=。成功注册的客户端日志为：

#+begin_example
rswap: Hermit RDMA backend registered
#+end_example

卸载 backend 前必须先停止使用相应 swap 设备并确保没有远端 entry 或未完成的
RDMA 请求。

* 控制面与 ABI

Hermit 控制项位于 =/sys/kernel/debug/hermit/=：

| 文件 | 含义 |
|-
| =bypass_swapcache= | 对远端 entry 使用 direct swapin |
| =speculative_io= | 在 fault 元数据工作前发起异步 load |
| =lazy_poll= | 对具体请求非阻塞 poll，未完成时继续等待 |
| =batch_swapout= | 保留的 batch swapout 控制项 |
| =batch_io= | 保留的 batch I/O 控制项 |
| =vaddr_swapout= | 保留的定向回收控制项 |
| =apt_reclaim= | 启用 memcg 异步回收 |
| =reclaim_mode= | =1= 时使用多个回收 work |
| =reclaim_headroom_pages= | 距离 =memory.max= 的主动回收余量，默认 2048 页 |
| =sthd_cnt= | 多 work 模式的 worker 数，最大 16 |
| =remote_order_mask= | 可写的传输 order 位图，默认 =0x1= |
| =effective_order_mask= | 只读的配置与 backend 能力交集 |
| =order_stats= | 逐 order 的 store/load/4 KiB fallback/error 计数 |

=remote_order_mask= 的 bit N 表示允许用 order N 的单个远端请求：bit 0 是
4 KiB，bit 2 是 16 KiB，直到 bit 9 的 2 MiB。bit 0 必须始终置位，bit 1
以及 bit 9 以上的位会被拒绝。例如只启用 4 KiB：

#+begin_src sh
echo 0x1 | sudo tee /sys/kernel/debug/hermit/remote_order_mask
#+end_src

启用 64 KiB 和 2 MiB，同时保留 4 KiB 回退：

#+begin_src sh
echo 0x211 | sudo tee /sys/kernel/debug/hermit/remote_order_mask
cat /sys/kernel/debug/hermit/effective_order_mask
cat /sys/kernel/debug/hermit/order_stats
#+end_src

该位图只选择 Hermit 的传输粒度，不修改 Linux 的
=/sys/kernel/mm/transparent_hugepage/= 分配策略。

RDMA 模块参数 =max_order= 决定单个 WR 支持的最大 order。它在模块加载时读取且
为只读参数；需要修改时先 =swapoff=、卸载模块，再用
=insmod rswap-client.ko ... max_order=N= 重新加载。异步 load context 使用预留
mempool，所有数据 CQ 使用 direct polling 并由队列锁串行化；大 WR 或部分
base-page submit 失败会在原请求完成后统一重试 4 KiB 路径。

=tools/rdma= 的 benchmark 默认保留当前 =reclaim_mode= 和
=reclaim_headroom_pages=，只有显式设置同名环境变量才会写入；结果目录中的
=reclaim_*_requested= 与 =reclaim_*_actual= 用于记录请求值和实际值。

保留的 x86-64 syscall ABI：

#+begin_example
471 reset_swap_stats(void)
472 get_swap_stats(int *ondemand, int *prefetch, int *hit_on_cache)
#+end_example

=get_swap_stats= 同时向 dmesg 输出原有字段名，包括 =Demand=、=Prefetch=、
=TotalSwapOut=、=TotalReclaim=、=major swap duration=、=RDMA read latency= 和
=Poll wait=。

* 当前边界

- Linux 6.18 的 PMD THP 可按 order 9 swapout；PTE swap fault 可聚合 order
  2–8 mTHP，当前不会把 order-9 swap entry 直接恢复成 PMD THP；
- DRAM backend 是功能验证工具，不模拟真实 RDMA 的时延、DMA 或设备错误；
- 外部 OFED RDMA 客户端可编译路径与真实 NIC/server 端到端测试是两级验证，
  后者必须在对应硬件环境完成；
- backend dispatch 使用 SRCU，RDMA client 还会等待 active I/O 和各队列已提交
  WR 完成后再释放资源；但 remote-only entry 没有本地副本，因此仍必须先
  =swapoff= 并确认成功，不能把该等待机制当成带活跃 swap 热卸载支持。
