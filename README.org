#+title: Hermit 6.6
#+startup: overview

* 简介

=hermit-6= 是 Hermit 从 Linux 5.14 迁移到 Linux 6.6 的工作目录。

当前内核位于 =linux-stable=，基线是 Linux =v6.6.138=，Hermit 修改在该内核
子仓库的 =hermit= 分支上。当前可运行目标包括 DRAM 模式和 RDMA 模式：
DRAM backend 用 QEMU 验证数据正确性和 profiling 输出；RDMA backend 已迁移到
=hermit_backend_ops=，用于实验室机器上的远端内存测试。

当前重点：

- 用 =hermit_backend_ops= 替代 5.14 依赖的 frontswap。
- 跑通 DRAM backend 的 swapout/store 和 swapin/load。
- 恢复 5.14 Hermit profiling 的主要观测点。
- 恢复 vaddr/vpage directed reclaim 的安全子集。
- 将 RDMA backend 从 frontswap 迁移到 =hermit_backend_ops=。
- 提供 QEMU DRAM 自动验证脚本。

* 当前功能状态

已完成：

- =CONFIG_HERMIT=、Hermit MM 文件和统计系统调用接入 Linux 6.6。
- x86-64 系统调用：

  #+begin_src text
  471 reset_swap_stats
  472 get_swap_stats
  #+end_src

- =do_swap_page()= 支持 =bypass_swapcache= direct swapin。
- =swap_readpage()= 和 =swap_writepage()= 支持 Hermit backend load/store。
- =hermit_backend_ops= 支持 =invalidate_page= / =invalidate_area=，swap slot
  释放和 =swapoff= 会清理 backend entry。
- DRAM/RDMA backend 使用完整 =swp_entry_t= 到 backend slot 的 XArray 映射，
  避免多个 swap 设备相同 offset 互相覆盖。
- direct bypass swapcache 路径恢复了保守的 VMA readahead/prefetch；prefetch
  页进入 swapcache，按需页仍绕过 swapcache。
- =remoteswap/client= 的 DRAM backend 已注册到 =hermit_backend_ops=。
- =remoteswap/client= 的 RDMA backend 已注册到 =hermit_backend_ops=。
- DRAM backend 提供 debugfs counter：

  #+begin_src text
  /sys/kernel/debug/rswap_dram/stores
  /sys/kernel/debug/rswap_dram/loads
  /sys/kernel/debug/rswap_dram/load_misses
  /sys/kernel/debug/rswap_dram/errors
  #+end_src

- RDMA backend 提供 debugfs counter：

  #+begin_src text
  /sys/kernel/debug/rswap_rdma/stores
  /sys/kernel/debug/rswap_rdma/loads
  /sys/kernel/debug/rswap_rdma/load_misses
  /sys/kernel/debug/rswap_rdma/post_errors
  /sys/kernel/debug/rswap_rdma/wc_errors
  /sys/kernel/debug/rswap_rdma/poll_loads
  /sys/kernel/debug/rswap_rdma/poll_stores
  #+end_src

- =vaddr_swapout= 已恢复 order-0、匿名、单映射页的安全子集。
- Hermit high reclaim worker 使用 =WQ_UNBOUND | WQ_MEM_RECLAIM= 专用
  workqueue，不再固定重排到单个 CPU。
- QEMU 验证会检查 checksum、=pswpin=、=pswpout=、backend store/load 计数和
  Hermit profiling dmesg。

未完成或限制：

- =ADC_POLL_STORE= 在 DRAM 同步 store 模式下预期为 0；RDMA store 会 post 后
  立即 poll/drain，尚未恢复 5.14 的跨页 batch async store。
- 大 folio、THP、复杂 MGLRU 路径优先保留 Linux 6.6 原生行为。
- 不建议在仍有 active swap entry 时 =rmmod rswap-client.ko=；测试中应先
  =swapoff=，QEMU 验证中可直接 poweroff。

* Profiling 说明

当前已恢复的主要类别：

- swap major/minor/non-swap fault duration。
- swapin =do_swap_page()= breakdown。
- backend read/write latency，仍使用 =ADC_RDMA_READ_LAT= 和
  =ADC_RDMA_WRITE_LAT= 名称以保持 5.14 ABI。
- memcg charge 和 reclaim breakdown。
- vmscan reclaim/swapout 中的 reference check、unmap、TLB flush、write page。
- swap readahead/prefetch 和 swapcache hit-on-prefetch。

正常可能为 0 的字段：

- =ADC_POLL_STORE=：DRAM backend 是同步 store；RDMA backend 触发 store 后
  立即 poll/drain 时应非 0。
- =ADC_HERMIT_RMAP1_LAT= / =ADC_HERMIT_RMAP2_LAT=：仅在 =vaddr_swapout= 开启、
  当前 reclaim 命中 order-0 匿名单映射页时非 0；kswapd、THP、KSM、hugetlb、
  large folio、多映射页会回退 native rmap。
- =ADC_PAGE_RECLAIM=：没有触发 memcg reclaim 时可能为 0。
- =ADC_PREFETCH= / =ADC_RD_CACHE_ASYNC=：关闭 readahead 或走 direct bypass
  swapcache 时可能为 0。

** [6/7] 5.14 → 6.6 移植遗留TODO

*** [x] 缺少 invalidate_page / invalidate_area 回调

已补齐。=hermit_backend_ops= 现在包含 =invalidate_page= 和
=invalidate_area=，并在 =swap_range_free()= 与 =swapoff= 路径调用：

- =swap_range_free()=：释放单个或一段 swap slot 时清理对应 backend entry。
- =swapoff=：关闭 swap 设备时清理对应 =swp_type= 的全部 backend entry。
- DRAM/RDMA backend 会同时清理 XArray 映射、used bitmap 和 valid bitmap。

*** [x] 缺少 per-swap-device bitmap 隔离

已补齐。DRAM/RDMA backend 不再直接用 =swp_offset(entry)= 作为远端 slot。
当前实现使用完整 =entry.val= 作为 XArray key，按需分配 backend slot：

- store：为完整 =swp_entry_t= 保留或复用一个 backend slot，写成功后置 valid。
- load：先查完整 entry 映射，再检查 valid；miss 返回 =-ENOENT=，回退 native
  swap read。
- invalidate：释放 entry 时归还 slot，避免 swapoff/swapon 后读到旧数据。

*** [ ] 跨页异步 store / batch swapout 路径未恢复

5.14 的 =vmscan.c= 使用 =frontswap_store_on_core= + =frontswap_poll_store= 实现
异步批量 swapout，=under_write_pages= 链表追踪进行中的写操作。6.6 的
=hermit_swap_writepage= 会调用 =hermit_backend_store(..., async=false)=，随后立即
=hermit_backend_poll_store(cpu)=，再继续 native swap write-through。RDMA backend
内部会 post =QP_STORE=，但 page_io 层马上 drain，不会像 5.14 一样跨多个页面批量
提交和延迟收割。

当前影响：
- DRAM backend 是同步 store，功能不受影响。
- RDMA backend 功能已恢复，但写路径保守，性能低于 5.14 的 batch async store。
- =ADC_POLL_STORE= 在 RDMA 下可以非 0，但它表示立即 drain，不等价于 5.14 的
  batch 完成路径。

*** [x] hermit_backend_peek_load 定义了但预取路径未调用

已接入 direct bypass swapcache 的保守 VMA prefetch。预取循环在每次提交
prefetch 前调用 =hermit_backend_peek_load(cpu)=：

- DRAM backend 的 =peek_load= 仍返回 1，表示不提前截断预取。
- RDMA backend 的 =peek_load= 查询 load queue pending counter；按需读完成后，
  prefetch 循环提前停止，避免继续发送无用请求。

*** [x] Hermit 自定义 readahead 函数未迁移

已恢复 direct bypass swapcache 场景下最关键的安全子集：

- 按需页仍由 =hermit_issue_read(..., async=true)= 直接读入非 swapcache folio。
- 邻近页通过 =__read_swap_cache_async()= 加入 swapcache，再走
  =swap_readpage()= → =hermit_swap_readpage()= → backend load。
- 该实现保留 6.6 原生 swapcache 生命周期，不复用 5.14 的旧 frontswap async
  page lock 语义。

*** [x] direct swapin async 已恢复，但 native read/store 仍是保守同步语义

direct bypass swapcache 路径中的 =hermit_issue_read()= 已调用
=hermit_backend_load(..., async=true)=，RDMA backend 会 post READ，后续由
=hermit_poll_read()= / =lazy_poll= 收口。native =swap_readpage()= fallback 仍用
=async=false=，store 路径也保持 post 后立即 poll 的写穿语义。

当前影响：
- direct swapin 的异步读功能已恢复。
- native swapcache read path 为同步 backend load。
- store 还没有恢复 5.14 的跨页 batch async。

*** [x] Hermit high reclaim worker 可能长时间占用 CPU

已改为专用 unbound workqueue：

#+begin_src text
alloc_workqueue("hermit_high_reclaim",
                WQ_UNBOUND | WQ_MEM_RECLAIM | WQ_CPU_INTENSIVE, 0)
#+end_src

同时 =memcg= cleanup 会 =cancel_work_sync()= 所有 Hermit reclaim work，避免
pending work 在 memcg 释放后继续访问旧对象。后续仍可进一步限制单次 reclaim
批量，这是性能调优项，不影响当前正确性。
