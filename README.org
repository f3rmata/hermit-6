#+title: Hermit 6.6
#+startup: overview

* 简介

=hermit-6.6= 是 Hermit 从 Linux 5.14 迁移到 Linux 6.6 的工作目录。

当前内核位于 =linux-stable=，基线是 Linux =v6.6.138=，Hermit 修改在该内核
子仓库的 =hermit= 分支上。当前可运行目标是 DRAM 模式：swapout 写入本地 DRAM
mock backend，swapin 再从同一个 backend 读回，用 QEMU 验证数据正确性和
profiling 输出。

当前重点：

- 用 =hermit_backend_ops= 替代 5.14 依赖的 frontswap。
- 跑通 DRAM backend 的 swapout/store 和 swapin/load。
- 恢复 5.14 Hermit profiling 的主要观测点。
- 提供 QEMU DRAM 自动验证脚本。

当前不包含完整 RDMA backend 迁移。RDMA 相关代码仍保留在 =remoteswap= 中，但
6.6 下第一轮验证请使用 ~BACKEND=DRAM~。

* 当前功能状态

已完成：

- =CONFIG_HERMIT=、Hermit MM 文件和统计系统调用接入 Linux 6.6。
- x86-64 系统调用：

  #+begin_src text
  471 reset_swap_stats
  472 get_swap_stats
  #+end_src

- =do_swap_page()= 支持 =bypass_swapcache= direct swapin。
- =swap_readpage()= 和 =swap_writepage()= 支持 Hermit backend load/store。
- =remoteswap/client= 的 DRAM backend 已注册到 =hermit_backend_ops=。
- DRAM backend 提供 debugfs counter：

  #+begin_src text
  /sys/kernel/debug/rswap_dram/stores
  /sys/kernel/debug/rswap_dram/loads
  /sys/kernel/debug/rswap_dram/load_misses
  /sys/kernel/debug/rswap_dram/errors
  #+end_src

- QEMU 验证会检查 checksum、=pswpin=、=pswpout=、backend store/load 计数和
  Hermit profiling dmesg。

未完成或限制：

- RDMA backend 尚未迁移到 =hermit_backend_ops=。
- Hermit vaddr/vpage directed reclaim 尚未完整恢复到 6.6 folio/rmap 路径。
- =ADC_POLL_STORE= 在 DRAM 同步 store 模式下预期为 0。
- 大 folio、THP、复杂 MGLRU 路径优先保留 Linux 6.6 原生行为。
- 第一轮不建议在仍有 active swap entry 时 =rmmod rswap-client.ko=；测试中直接
  QEMU poweroff。

* Profiling 说明

当前已恢复的主要类别：

- swap major/minor/non-swap fault duration。
- swapin =do_swap_page()= breakdown。
- backend read/write latency，仍使用 =ADC_RDMA_READ_LAT= 和
  =ADC_RDMA_WRITE_LAT= 名称以保持 5.14 ABI。
- memcg charge 和 reclaim breakdown。
- vmscan reclaim/swapout 中的 reference check、unmap、TLB flush、write page。
- swap readahead/prefetch 和 swapcache hit-on-prefetch。

正常可能为 0 的字段：

- =ADC_POLL_STORE=：DRAM backend 是同步 store。
- =ADC_HERMIT_RMAP1_LAT= / =ADC_HERMIT_RMAP2_LAT=：vaddr/vpage reclaim 尚未完整恢复。
- =ADC_PAGE_RECLAIM=：没有触发 memcg reclaim 时可能为 0。
- =ADC_PREFETCH= / =ADC_RD_CACHE_ASYNC=：关闭 readahead 或走 direct bypass
  swapcache 时可能为 0。

完整点位映射见：

* 重要路径

Hermit direct swapin：

#+begin_src text
do_swap_page()
  -> swap_cache_get_folio() miss
  -> HMT_BPS_SCACHE && swap_count == 1
  -> hermit_direct_swap_readpage()
  -> hermit_backend_load()
  -> hermit_poll_read()
  -> set_pte_at()
#+end_src

#+begin_src text
do_swap_page()

  -> swap_readpage()

  -> hermit_backend_load()

  -> hermit_backend_store()

** [/] 5.14 → 6.6 移植遗留问题

以下问题不影响单次 DRAM swapout→swapin→校验测试，但在多轮测试或多 swap 设备场景
下可能导致错误。

*** [ ] 缺少 invalidate_page / invalidate_area 回调

=hermit_backend_ops= 没有 swap entry 失效或 swapoff 的通知回调。5.14 的
=frontswap_ops= 包含 =invalidate_page= 和 =invalidate_area=，当 swap slot 被释放
或 swap 设备被关闭时自动清除后端中的对应页面。

当前影响：
- DRAM backend 的 =local_dram_valid= bitmap 在 swap slot 被释放后不会清除。
- swapoff→swapon 循环中，旧 swap entry 的 bitmap bit 仍然为 1，新 swapout 可能
  分配到同一 offset，读取时命中的是上一轮的旧数据。

*** [ ] 缺少 per-swap-device bitmap 隔离

5.14 的 =frontswap_map= 是 per-swap-device 的 bitmap，每个 swap 设备独立追踪。
6.6 DRAM backend 使用单一的全局 =local_dram_valid= bitmap，offset 仅由
=swp_offset(entry)= 计算，不区分 =swp_type=。

当前影响：
- 同时挂载多个 swap 设备时，type=0 offset=100 和 type=1 offset=100 映射到 DRAM
  中同一位置，互相覆盖。

*** [ ] 异步 store / batch swapout 路径未迁移

5.14 的 =vmscan.c= 使用 =frontswap_store_on_core= + =frontswap_poll_store= 实现
异步批量 swapout，=under_write_pages= 链表追踪进行中的写操作。6.6 的
=hermit_swap_writepage= 仅调用 =hermit_backend_store(..., async=false)= 做同步写，
=hermit_post_pageout_rls_pages= 和 =ADC_POLL_STORE= 的 batch 完成路径未迁移到
6.6 =vmscan.c=。

当前影响：
- DRAM backend 是同步 store，功能不受影响。
- RDMA backend 迁移后将无法使用异步批量提交，写性能会退化。

*** [ ] hermit_backend_peek_load 定义了但预取路径未调用

5.14 的 =swap_state.c= 预取循环中使用 =frontswap_peek_load(cpu)= 检测按需读是否
已完成，若完成则提前退出预取循环。6.6 中 =hermit_backend_peek_load= 已在
=hermit_backend.c= 实现并导出，但 =swap_state.c= 的预取路径未调用。

当前影响：
- DRAM backend 的 =peek_load= 始终返回 1（未完成），预取检查逻辑本身不依赖它，
  暂无实际影响。
- RDMA backend 迁移后预取可能继续发送无用请求。

*** [ ] Hermit 自定义 readahead 函数未迁移

5.14 提供了四个后端感知的 readahead/prefetch 函数：
=hermit_swapin_readahead=、=hermit_swap_cluster_readahead=、
=hermit_vma_prefetch=、=hermit_swap_ra_info=。6.6 使用标准内核的
=swapin_readahead= / =swap_cluster_readahead=，这些函数不直接与 backend 交互。

当前影响：
- DRAM backend 下 readahead 走 =swap_readpage= → =hermit_swap_readpage= →
  =rswap_dram_read= 路径，功能正常。
- 但 bypass swapcache direct swapin 路径（=hermit_direct_swap_readpage=）中
  没有预取逻辑，5.14 的 =hermit_swapin_bypass_swapcache= 中自带的
  =hermit_vma_prefetch= 在 6.6 中缺失。

*** [ ] async 参数始终为 false

内核侧所有调用点传给 =hermit_backend_load= 和 =hermit_backend_store= 的 =async=
参数均为 =false=。5.14 的 =load_async= / =store_on_core= 异步路径未接入。接口中
的 =async= 参数目前是死代码。

当前影响：
- DRAM backend 忽略 =async= 参数，无实际影响。
- RDMA backend 迁移后需要将对应路径改为 =async=true= 才能使用异步读写。
